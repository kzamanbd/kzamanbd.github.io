# kzaman.com search audit — 15 Aug 2026

Technical SEO, AEO, GEO and entity audit. Every technical finding below was verified against
the deployed site and against `main` at commit `1d10913`, by live HTTP request or by source
inspection. Ranking, traffic and backlink claims are absent because no verified Search Console
or link data was available.

Sections marked **✅ Fixed** were repaired in this pass; see [What was fixed](#what-was-fixed)
for the diff-level summary and [What is still open](#what-is-still-open) for the rest.

---

## 1. Verdict

The brief asked for kzaman.com to become "one of the most visible, authoritative and frequently
cited websites in its relevant topics". Stated that way it will not happen, and chasing it wastes
the year.

The topics currently declared on the site — PHP, Laravel, React, Next.js, system design, MySQL,
Docker — are the most contested informational space on the technical web. Those SERPs are held by
first-party documentation, Stack Overflow, MDN, DigitalOcean, freeCodeCamp and vendor blogs with
six-figure link profiles. A one-person site with a single article and effectively no external link
equity does not enter that market. Neither do AI answer engines pull from it, because retrieval for
those queries is saturated with corpora the models were already trained on.

The winnable version of the goal is narrower and much more valuable: **own the engineering
territory nobody with authority is writing about, where first-hand access is the moat.** Concretely
that is Dokan and WordPress multi-vendor marketplace engineering, WordPress plugin performance and
debugging at scale, and the WordPress–Laravel seam. In that space the competition is documentation
written for store owners, not engineers — and there is no engineering-depth source for a language
model to cite.

> **Strategy in one sentence.** Stop competing for generic backend topics; become the primary
> engineering source on multi-vendor WordPress commerce — publishing measurements, benchmarks and
> failure post-mortems that only someone inside that codebase can produce — while consolidating the
> fragmented `Kamruzzaman` person entity onto kzaman.com.

## 2. Critical defects

### C-01 — Three routes self-canonicalised to the homepage ✅ Fixed

`src/app/layout.tsx` set `alternates.canonical = siteURL` in the root layout. Next merges metadata
down the segment tree, so every route that did not set its own canonical inherited the homepage URL:

```
curl -s https://kzaman.com/resume               → <link rel="canonical" href="https://kzaman.com"/>
curl -s https://kzaman.com/plugins/debug-suite  → <link rel="canonical" href="https://kzaman.com"/>
curl -s https://kzaman.com/shorturl             → <link rel="canonical" href="https://kzaman.com"/>
```

Google treats a canonical pointing at another URL as a strong consolidation signal. `/resume` — the
single highest-intent page on a personal site — was telling Google it is a duplicate of the
homepage.

**Fix applied.** Root canonical changed to `'./'`, which Next resolves per-route against
`metadataBase`. Verified in the build output: every route now emits its own URL.

### C-02 — The old GitHub Pages site is still live ⚠️ Open (not fixable from this repo)

`https://kzamanbd.github.io/` returns **200**, serving a stale portfolio (last modified 9 Oct 2025)
titled `KAMRUZZAMAN | Portfolio`. No canonical tag, no `robots.txt`, no sitemap. It is the older
property, so for brand queries like _kzamanbd_ or _Kamruzzaman portfolio_ it competes directly with
kzaman.com and splits whatever historical equity exists.

**What to do.** Replace the Pages deployment with a minimal page carrying
`<link rel="canonical" href="https://kzaman.com/">`, `<meta name="robots" content="noindex,follow">`
and a visible link to kzaman.com. Do not simply delete it — a 404 discards the equity instead of
passing it. GitHub Pages cannot issue a 301, so canonical-plus-noindex is the strongest signal
available. This lives in GitHub Pages settings, not in this repository.

### C-03 — Structured data contained fabricated engagement metrics ✅ Fixed

`src/utils/jsonLd.ts` emitted an `interactionStatistic` block on every page claiming 15 follows,
205 likes and 66 write actions. Those numbers corresponded to nothing. It also set `dateCreated`
and `datePublished` to `new Date().toISOString()`, so the profile claimed to have been created at
build time and the claim changed on every deploy.

This is structured data that does not represent anything on the page — the category Google's spam
policies treat as misleading, and exactly the signal an AI system uses to decide a source is not
trustworthy.

**Fix applied.** `interactionStatistic`, `agentInteractionStatistic` and both dynamic dates removed.

### C-04 — `ProfilePage` schema on every page, including articles ✅ Fixed

`JsonLdScript` rendered from the root layout, so the article page emitted both a `BlogPosting` and
a `ProfilePage` whose `url` was the homepage:

```
https://kzaman.com/articles/how-netflix-streams-one-movie-to-190-countries
  BlogPosting    ×1   ← correct
  ProfilePage    ×1   ← wrong page type, url points at /
  BreadcrumbList ×1   ← correct
```

`ProfilePage` declares "this page is a profile of a person". On an article that is false, and it
competes with the `BlogPosting` for main-entity interpretation. The site also had no `WebSite` node
at all — the node that establishes site-level identity.

**Fix applied.** The graph is split. Sitewide, an `@graph` carries a `WebSite` node
(`@id: <site>#website`, `publisher` → `#person`) and the `Person` node (`@id: <site>#person`).
`ProfilePage` renders only on `/`, with `mainEntity` referencing `#person` by `@id` rather than
restating it. Article and breadcrumb markup were already correct and already referenced `#person`.

## 3. Technical findings

The foundations are good and worth stating: HTTPS with HSTS, clean 404s, `www` and trailing-slash
both 308 to the canonical host, server-rendered HTML with real text (1,091 words on the homepage
before any JavaScript runs), three working feeds, correct `BlogPosting` markup, prerendered routes
on a Vercel edge cache. Most personal sites fail here. The remainder:

### T-01 — `/plugins/debug-suite` was an orphan on all three axes ✅ Fixed

Zero internal links pointed to it — the project card linked to `wordpress.org/plugins/debug-suite/`
instead. It was absent from `sitemap.ts`. Its canonical pointed at the homepage (C-01). It had no
`description` in its metadata export. The site's only product page was invisible three ways.

**Fix applied.** Linked from the project card as an internal "Overview" link (the wordpress.org link
stays as a secondary action), added to the sitemap, given a description, its own canonical, OG tags
and `SoftwareApplication` markup whose `author` references `#person`.

### T-02 — Four dead outbound links on the homepage ✅ Fixed

```
https://wp.kzaman.me                  → DNS failure (000)
https://typeon.kzaman.me              → DNS failure (000)
https://console.kzaman.me             → DNS failure (000)
https://www.draftscripts.com/tenancy  → 404
```

These were the live-demo links on project cards. A page that claims shipped work and then links to
nothing contradicts its own experience claim, visibly, to a human evaluator and a crawler alike.

**Fix applied.** All dead demo links removed; repository links retained. Per the decision to run one
entity, the `draftscripts.com` link was removed as well and the contact sender default moved from
`hello@draftscripts.com` to `hello@kzaman.com`.

### T-03 — `/resume` inherited the homepage title and description ✅ Fixed

`src/app/resume/page.tsx` exported no `metadata`, so the page shipped as
`<title>Kamruzzaman - Software Engineer</title>` with the homepage description — identical to `/`.
Combined with C-01, that gave Google three independent reasons to fold the page into the homepage.

**Fix applied.** Title, description, canonical and OG tags added. The title uses `absolute` so the
root `%s | Kamruzzaman` template does not append a second copy of the name.

### T-04 — The experience claim contradicted itself ✅ Fixed

The meta description said "5+ yrs"; the homepage stat tile rendered "4+ Years Experience"; the
resume summary said "4+ years"; `careerExperience` computed `currentYear - 2021` and drifted. The
resume's own earliest role starts May 2020.

**Fix applied.** A single `careerStart = 2020-05-01` constant now drives `careerExperience`, and the
hero tile, about copy, resume summary and JSON-LD description all derive from it. Current value: 6+.

### T-05 — Name-string inconsistency ✅ Fixed

Schema `name` was `KAMRUZZAMAN`, the resume heading `MD KAMRUZZAMAN`, LinkedIn `Md Kamruzzaman`.
Search engines resolve a person entity by matching the same string across properties.

**Fix applied.** `authorName` is now `Md Kamruzzaman` everywhere on this site — hero, schema, feeds,
article author, OG tags. `kzamanbd` remains the `alternateName`. The external profiles still need
the same treatment; see [What is still open](#what-is-still-open).

### T-06 — Sitemap hygiene ✅ Fixed

`sitemap.ts` avoided wall-clock `lastmod` for articles, then set `lastModified: new Date()` for `/`,
`/resume` and `/now` anyway. Google ignores `changefreq` and `priority` entirely and discounts
`lastmod` once it is provably wrong. `/plugins/debug-suite` was missing.

**Fix applied.** Static routes carry a hand-maintained `lastmod` map, `changefreq` and `priority`
are gone, and `/plugins/debug-suite` is included.

### T-07 — Fabricated plugin metrics on `/plugins/debug-suite` ✅ Fixed

Discovered during the fix pass, and the same class of problem as C-03 but user-visible. The page
hardcoded:

| Claimed on the page     | Actual (wordpress.org API) |
| ----------------------- | -------------------------- |
| 25,000+ downloads       | 713                        |
| 4.8 rating              | no rating                  |
| 487 reviews             | 0                          |
| 10,000+ active installs | below the reporting floor  |
| v1.0.0, July 2024       | v2.0.1, July 2026          |
| WordPress 6.0+          | WordPress 6.8+             |

The page also carried the copy "Join thousands of WordPress developers who trust Debug Suite".

**Fix applied.** `src/lib/wordpress-plugin.ts` reads the directory API at build time with a one-day
revalidate; a failed fetch resolves to `null` and the affected UI simply does not render. Every
number on the page now comes from the directory, figures the directory does not publish are omitted
rather than invented, and no `aggregateRating` is emitted. The "thousands of developers" line is
replaced with a claim that is true.

### T-08 — Three dead CTAs on the plugin page ✅ Fixed

"Download Free" and "Live Demo" were `<button>` elements with no handler. "View Source" linked to
`https://github.com` — the homepage of GitHub. A second CTA block at the foot of the page had two
more dead buttons.

**Fix applied.** Download → the wordpress.org listing; View source → the real repository; Read the
docs → the repository README. The Live Demo button is gone, because there is no hosted demo.

### T-09 — Payload ✅ Fixed

`/kzaman.jpg` was **495 KB** at 3422×3480, rendered at 342×348, and referenced directly as the
sitemap image. Compressed transfer was otherwise healthy: homepage HTML 48 KB, largest chunk 67 KB,
TTFB ~0.3 s from a cache HIT.

**Fix applied.** Resized to 1026×1044 (exactly 3× the render size, so the declared aspect ratio is
preserved) at quality 82: **495 KB → 173 KB**. A modern `browserslist` was added to `package.json`;
Next still emits a polyfill chunk, so treat that part as unresolved and low priority.

### T-10 — `/shorturl/<code>` was crawlable ✅ Fixed

User-supplied redirects on your own domain are a standard vector for lending a domain's name to
whatever it points at.

**Fix applied.** `Disallow: /shorturl/` added to `robots.ts`. The tool's own page stays indexable.
`/articles/search` is deliberately **not** blocked: it carries a `noindex` tag, and a crawler blocked
in robots.txt can never fetch the page to see it.

### T-11 — Tags exist only as query parameters ⏸ Deferred, correctly

Tag filtering happens at `/articles?tag=X` with the canonical pinned to `/articles`. That is correct
today — with one article, a tag hub would be a thin page. It does mean there is no crawlable topic
hub, which is the main mechanism for demonstrating topical depth once a corpus exists.

**When to act.** Once a tag holds five or more articles, promote it to `/articles/topic/[slug]` with
its own H1, a written 150-word introduction to the topic (not a bare list), `CollectionPage` markup
and its own canonical. Leave sparse tags as query filters.

## 4. Things not to do

| Tactic                             | Verdict           | Reasoning                                                                                                                                                             |
| ---------------------------------- | ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `llms.txt`                         | Skip              | No major AI system has confirmed it reads this file. Retrieval fetches normal HTML. The site already ships three feeds and a clean sitemap.                           |
| AI-crawler rules in `robots.txt`   | Leave as-is       | `User-Agent: *  Allow: /` already permits GPTBot, ClaudeBot, PerplexityBot and Google-Extended. Explicit allows change nothing; disallows would destroy the GEO goal. |
| FAQ schema for rich results        | Low value         | Google restricted FAQ rich results to government and health sites in Aug 2023. Useful only as a parsing aid where a real FAQ exists.                                  |
| hreflang                           | Not applicable    | Single-language site.                                                                                                                                                 |
| Publishing volume for its own sake | Counterproductive | Twenty generic Laravel tutorials would rank for nothing and dilute the topical signal. Eight articles nobody else can write beats eighty that anyone could.           |

## 6. Entity strategy

A search for _kzaman.com Kamruzzaman software engineer weDevs_ returns LinkedIn, a contact-scraper
page, then five unrelated people named Kamruzzaman (Fiserv, SELISE, Metarouge, Bayt) plus a
Wikipedia entry for Kazi Kamruzzaman. kzaman.com does not appear. The name is common in Bangladesh
and is already attached to a stronger entity in Google's knowledge graph.

The bare name is not winnable. The **disambiguated entity** is: _Kamruzzaman weDevs_, _Kamruzzaman
Dokan_, _kzamanbd_. That requires the same identifier appearing consistently across every property
Google already crawls, all pointing back to kzaman.com as the hub.

1. **One name string everywhere: `Md Kamruzzaman`.** ✅ Done on this site. Still needs doing on
   LinkedIn, the GitHub profile name and the wordpress.org profile.
2. **Expand `sameAs`.** ✅ Done: LinkedIn, GitHub, wordpress.org, LeetCode, Codeforces, YouTube, X,
   Facebook. The `mailto:` was dropped — it is not a profile URL.
3. **Reciprocate every link.** A `sameAs` claim is worth what the destination confirms. Each of
   those profiles should carry `kzaman.com` in its website field. Cheapest entity win available.
4. **Fix the empty Medium profile.** It is linked from the homepage and has zero stories. Either
   publish there with canonicals pointing home, or remove the link.
5. **Bind person to organisation and product.** ✅ Done: `Person.worksFor` → weDevs, and
   `SoftwareApplication.author` → `#person` on the plugin page. This is what lets a model answer
   "who builds Dokan's marketplace layer" with a name.
6. **One entity, one domain.** ✅ Decided and applied: kzaman.com only. `kzaman.me` and
   `draftscripts.com` references are removed from the site. Two loose ends remain outside this
   repo — the YouTube channel is still branded DraftScripts, and the plugin's own `Plugin URI`
   header points at `https://kzaman.me/plugins/debug-suite`, which is a dead domain and needs a
   plugin release to correct.

### The format contract for every article

This is the AEO and GEO work, and it is structural rather than stylistic. Retrieval systems chunk
pages and score chunks; a page that buries its answer 800 words down loses to one that states it in
the first 60.

1. **H1 states the question, not a slogan.** A 40–60 word direct answer immediately below it, before
   any preamble, self-contained enough to stand alone if extracted.
2. **Evidence follows the claim, not the reverse.** Number, measurement, code or version, in the
   same section as the claim it supports.
3. **One idea per H2, phrased as the query someone types.** Each section should survive being read
   on its own.
4. **Tables for anything comparative.** They chunk cleanly and are disproportionately quoted by
   generative systems.
5. **Explicit versions and dates.** "Dokan 3.x, WordPress 6.5, measured May 2026". Specificity is
   what separates a citable source from a plausible one.
6. **Attribute every external claim with a link.** Sources that cite are cited.
7. **Publish the methodology for any number you produce.** An unexplained benchmark is not trusted
   by a reviewer or a model; a reproducible one becomes the reference.

### On AI citations, honestly

No tactic guarantees a citation. What is observable in what these systems surface: they favour pages
with unique numbers, clear attributive sentences, explicit dates and versions, and named authors
with verifiable credentials. What is **not** established: that schema markup increases citation
probability, that `llms.txt` is read, or that any published "AI visibility score" measures something
stable. Optimise for the first list; ignore vendors selling the second.

## 8. Distribution

There is no meaningful external link profile and no budget for digital PR. That rules out most of
the standard playbook — but a working plugin and a real employer give three channels most personal
sites lack.

- **wordpress.org is the highest-authority reachable property.** The Debug Suite listing, the
  profile page and the plugin support forum all carry weight and topical relevance. Keep the plugin
  maintained, put kzaman.com in the plugin URI header (currently a dead `kzaman.me` URL), and answer
  support threads under your own name. Worth more than twenty guest posts.
- **weDevs engineering blog.** Author under your own name with a bio linking to kzaman.com. A
  relevant link from an established WordPress-industry domain is exactly the corroboration the
  entity strategy needs.
- **Original research is the only asset that earns unsolicited links.** Items 02 and 03 exist for
  this reason. A debug-log distribution dataset is what WP Tavern, Post Status and the WordPress
  newsletters cover.
- **Where WordPress engineers already are:** Post Status Slack, WP Tavern comments, Advanced
  WordPress, r/ProWordPress. Participate as a contributor, not a link-dropper — unlinked brand
  mentions still build entity association, and these communities punish self-promotion hard.
- **Conference and podcast circuit:** WordCamp Dhaka and the regional WordCamps, plus WordPress
  podcasts. Speaker pages are high-quality contextual links; the barrier is a proposal, not a budget.
- **GitHub as a discovery surface:** repositories rank and get crawled. Every README should link
  kzaman.com and, where an article explains the code, link that article.

Explicitly out: paid links, PBNs, mass guest-posting, directory blasts, anchor-text campaigns. At
this size a manual action would be unrecoverable, and none of it produces AI citations regardless.

## 9. Measurement

### Reliable

- **Search Console** — impressions, clicks, average position, and the Pages report for indexed vs
  excluded. After the C-01 fix, watch specifically for `/resume`, `/shorturl` and
  `/plugins/debug-suite` moving out of "Alternate page with proper canonical tag". That transition
  is the proof the fix worked.
- **Bing Webmaster Tools** — independently worth verifying; Bing's index feeds Copilot and is far
  more generous with query data at low volume.
- **URL Inspection** after each deploy for pages that changed.
- **Rich Results Test and the Schema validator** on `/`, `/resume`, an article and the plugin page.
- **Server logs / Vercel analytics for crawler hits** — GPTBot, ClaudeBot, PerplexityBot, Googlebot.
  Crawl frequency by user agent is the most direct evidence that AI systems can see the site at all.

### Proxy only — treat with suspicion

- **Manual AI-engine spot checks.** Keep a fixed list of ~15 questions the content should answer,
  run them quarterly across ChatGPT, Perplexity, Claude, Copilot and AI Overviews, and record
  whether kzaman.com is cited and who is cited instead. Directional signal, not a metric: answers
  are non-deterministic, personalised, and change with model updates. Do not trend-line it.
- **Third-party "AI visibility" tools.** They sample the same non-deterministic surface and present
  it as a score.
- **Referral traffic from AI engines.** Real when it appears, but most citations produce no click,
  so absence proves nothing.

### Honest expectations

With one article and no links, "meaningful organic traffic in six months" is not a realistic goal.
Realistic milestones:

| Milestone                                                         | When                                               |
| ----------------------------------------------------------------- | -------------------------------------------------- |
| All site pages correctly indexed                                  | 30 days post-fix                                   |
| Ranking for _kzamanbd_ and _Kamruzzaman weDevs_                   | 60–90 days                                         |
| First long-tail Dokan-query rankings, with eight articles live    | Month 4–6                                          |
| First observed AI citation, most likely off an original-data page | Month 6–12, maybe never from a query you predicted |

### New findings this round

**R-01 — Two social profiles in `sameAs` returned 404. ✅ Fixed.**
`https://www.youtube.com/@draftscripts` and `https://x.com/_kzamanbd` both returned 404 under a
browser user agent, against controls (`@google`, `x.com/jack`) that returned 200 — so this was a
real dead handle, not bot-blocking. Both accounts had moved to `kzamanhq`, confirmed by the X bio
matching the Medium profile. A `sameAs` entry pointing at a 404 is worse than no entry: it is a
claim the destination cannot corroborate.

**R-02 — `twitter:creator` still carried the dead handle. ✅ Fixed.**
`src/app/layout.tsx` hardcoded `@_kzamanbd` separately from `user.twitter`, so updating the profile
URL left every social card crediting an account that 404s. It is now derived from `user.twitter`.

**R-03 — The plugin page title carried a second brand. ✅ Fixed.**
`getTitle()` appended `- DraftScripts Showcase`, so the title read
`Debug Suite - WordPress Plugin - DraftScripts Showcase | Kamruzzaman` — two brands and a duplicated
name, on the one page that should read as a kzaman.com product. The helper and its unused sibling
`getDescription()` were deleted; the page sets its own title.

**R-04 — Title template used a different name string than the schema. ✅ Fixed.**
The root template was `%s | Kamruzzaman` while `Person.name` had become `Md Kamruzzaman`. Both now
derive from `authorName`.

**R-05 — The Pages shell serves HTTP 404 on deep paths. ⚠️ Accepted limitation.**
GitHub Pages returns a 404 status for any unmatched path, and the shell is served as `404.html`.
Crawlers do not follow canonicals or redirects on a 404 response, so only the root `/` (HTTP 200)
actually passes a signal. Impact here is negligible — the old github.io site was a single page, so
there are no indexed deep URLs to preserve — and Pages offers no way to return 200 for arbitrary
paths. Worth knowing rather than worth fixing.
